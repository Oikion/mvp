# Oikion — Impeccable Design Context

## Design Context

### Users

**Primary users**: Greek real estate agents and agency administrators (teams of 2–20 people).

**Context of use**: Agents work in bright offices, at client desks, and on laptops during property viewings. They switch between MLS (browsing/publishing listings), CRM (managing contacts, requests, and deals), and Oikosync (team activity feed). The product is task-dense — a typical session involves filtering, comparing, and updating dozens of records.

**Job to be done**: Move deals forward without friction. Find the right property for a client, record who owns a relationship, and keep the team in sync — all without the software getting in the way.

**Greek-specific considerations**: The UI uses both Greek (`el`, default) and English (`en`) locales. Greek text is morphologically complex — longer word forms, diacritics, and mixed uppercase/lowercase. Typography must remain legible and not feel cramped when switching from English to Greek. Line-height and spacing choices should be tested against Greek body copy, not just English.

---

### Brand Personality

**Three words**: Calm, trustworthy, efficient.

**What this means in practice**:
- *Calm*: The interface absorbs complexity so agents don't feel it. No pulsing badges, no intrusive toasts, no decorative motion that serves no informational purpose.
- *Trustworthy*: Precision builds confidence. Consistent spacing, predictable hover states, clear confirmation patterns, and data that looks accurate (correct decimal alignment, readable numbers, status badges that distinguish well).
- *Efficient*: Nothing earns a pixel unless it speeds up a task. Information density is a feature, not a problem to hide.

**Emotional goal**: An agent should open the dashboard and immediately feel oriented. The interface tells them where things stand without making them work for it.

**Anti-references**: Generic Bootstrap admin panels, purple-gradient SaaS homepages, Canva-aesthetic card-heavy layouts, sites that use border-left accent stripes as the primary visual language.

---

### Aesthetic Direction

**References**: Linear, Vercel, Raycast.

**What these references share**:
- Extremely crisp typography hierarchy — sizes differ meaningfully, not decoratively
- Dark mode that's first-class, not an inversion of light mode
- Generous use of negative space in headers and navigation, compressed in data-dense areas
- No decorative gradients; color is used functionally (status, selection, error)
- Monochromatic or near-monochromatic palettes with a single sharp accent

**Theme**: Light and dark are equally first-class. Neither is a fallback. Each mode has its own surface hierarchy — light mode uses subtle borders and background tints; dark mode uses elevation layers and opacity.

**Visual tone**: Refined utility. This is closer to a precision instrument than a consumer app. Think: the readout panel of a high-end architectural visualization tool, not a real estate listing portal.

---

### Typography Direction

**Current fonts**:
- **gallery.otf** — logo only. Never use in body, headings, or UI components.
- **Manrope** — current primary font. Retained as a baseline but should be evaluated for replacement.
- **Inter** — scheduled for removal. Do not use in any new code; replace on sight.

**Font exploration guidance**:
Oikion wants to move away from the Inter/Manrope monoculture toward something that feels more intentional. The ideal replacement is a grotesque or humanist sans-serif with these properties:
- Strong at small sizes (10–14px) — agents read dense tables
- Distinctive without being loud — recognizable, not decorative
- Greek character support (Unicode range including Greek Extended)
- Available as a variable font (performance and weight flexibility)

**Candidates to evaluate** (not a final decision — present options when implementing):
- **Geist** (Vercel's typeface) — precise, slightly humanist, excellent screen rendering, aligns with Vercel reference
- **Bricolage Grotesque** — variable, optically nuanced, less common, good Greek coverage
- **Chivo** — quiet confidence, narrow tracking, works dense
- **Hanken Grotesk** — calibrated neutrality with enough character to avoid monoculture

**Type scale**: Fixed `rem` sizes for app UI (not fluid/clamp — no major design system uses fluid type in product UI). Use a minimum 5-step scale with at least a 1.25× ratio between steps. Current scale (h1–h4 + body + caption) is acceptable but should increase contrast between h3/h4 and body.

### Design Principles

1. **Systematic over stylistic** — Every visual decision should be derivable from tokens. A coherent system beats a collection of beautiful one-offs. When introducing a new pattern, ask: does this fit the token system, or does it require a new token?

2. **Information earns its pixels** — No decorative elements unless they make data faster to read or safer to trust. This bans: side-stripe border accents, gradient text, sparklines used as decoration, and hover effects that convey nothing actionable.

3. **Equal-mode design** — When building a component, design light and dark simultaneously. Dark mode is not "add a .dark class." It has different surface elevations, different opacity strategies, and often different visual weights.

4. **Greek-text first** — Typography and spacing decisions should be validated against Greek body copy. Fallback: measure average word length in Greek UI strings vs English; Greek is ~30% longer, so compact layouts may need review.

5. **Calm confidence** — Motion should be functional (state transitions, entrance/exit) not ambient (background pulse, idle shimmer). Prefer `ease-out-quart` deceleration. Maximum one meaningful animation per user action.

---

### Current State & Evolution Intent

The current website and app UI are functional but acknowledge they were scaffolded with AI-generated templates. The design system is evolving from that baseline toward something with a distinct, owned aesthetic.

**Evolution strategy**:
- Replace Inter with a chosen alternative across all surfaces (one PR, not piecemeal)
- Migrate color tokens from HSL to OKLCH for perceptual uniformity
- Establish a proper 4pt spacing vocabulary (named tokens: `--space-xs`, `--space-sm`, `--space-md`, `--space-lg`, `--space-xl`, `--space-2xl`) to replace ad-hoc Tailwind spacing classes
- Apply consistent surface hierarchy to dark mode (currently uses a flat zinc-based inversion)

Impeccable should recommend toward this direction when critiquing or polishing. Do not preserve AI-template patterns out of inertia — replace them if they conflict with the principles above.
