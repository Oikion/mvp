# Phase A: Cascade Safety & Deletion Unification — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make user deletion/departure safe for org data by fixing DB cascades, unifying 5 deletion pathways into a single departure service, and adding null-safety across the UI.

**Architecture:** A single `handleUserDeparture(userId, orgId, reason)` function replaces 4 inconsistent deletion code paths. Schema changes make user-reference fields nullable with `onDelete: SetNull` for org data and `onDelete: Cascade` for personal data. UI components use a `getUserDisplay()` helper for null user references.

**Tech Stack:** Prisma ORM (PostgreSQL), Next.js 16, Clerk authentication, next-intl (i18n), TypeScript

**Spec:** `docs/superpowers/specs/2026-03-10-phase-a-cascade-safety-deletion-unification-design.md`

Create `lib/user-departure/index.ts`:

```typescript
import { prismadb } from "@/lib/prisma";
import { isOrgPersonal } from "@/lib/personal-workspace-guard";
import { nullifyOrgReferences } from "./nullify-org-references";
import { DepartureReason } from "@prisma/client";
import type { DepartureResult } from "./types";

export { DepartureReason } from "@prisma/client";
export type { DepartureResult } from "./types";

export async function handleUserDeparture(
  userId: string,
  orgId: string,
  reason: DepartureReason
): Promise<DepartureResult> {
  const result: DepartureResult = {
    orgId,
    reason,
    nulledReferences: 0,
    deletedPersonalData: 0,
    errors: [],
    timestamp: new Date(),
  };

  // Step 1: Pre-flight checks
  const user = await prismadb.users.findUnique({ where: { id: userId } });
  if (!user) {
    result.errors.push("User not found");
    return result;
  }

  if (await isOrgPersonal(orgId)) {
    result.errors.push("Cannot depart from a personal workspace");
    return result;
  }

  // Step 2: Check encryption key safety
  const orgEncKeys = await prismadb.organizationEncryptionKey.findMany({
    where: { organizationId: orgId },
    select: { userId: true },
  });
  const otherKeyHolders = orgEncKeys.filter((k) => k.userId !== userId);
  if (orgEncKeys.length > 0 && otherKeyHolders.length === 0) {
    result.errors.push(
      "Cannot depart: this user holds the only encryption key for the org. " +
      "Another user must be granted access first."
    );
    return result;
  }

  // Step 3: Null out org-scoped references
  const { nulledCount } = await nullifyOrgReferences(userId, orgId);
  result.nulledReferences = nulledCount;

  // Step 4: Delete user-personal data for this org
  const [notifs, invitees, encKeys] = await prismadb.$transaction([
    prismadb.notification.deleteMany({
      where: { userId, organizationId: orgId },
    }),
    prismadb.eventInvitee.deleteMany({
      where: { userId, CalendarEvent: { organizationId: orgId } },
    }),
    prismadb.organizationEncryptionKey.deleteMany({
      where: { userId, organizationId: orgId },
    }),
  ]);
  result.deletedPersonalData = notifs.count + invitees.count + encKeys.count;

  // Step 5: Audit log
  console.log(
    `[UserDeparture] userId=${userId} orgId=${orgId} reason=${reason} ` +
    `nulled=${result.nulledReferences} deleted=${result.deletedPersonalData}`
  );

  return result;
}
```

```typescript
type UserLike =
  | { name?: string | null; email?: string | null; avatar?: string | null }
  | null
  | undefined;

type UserDisplay = {
  name: string;
  email: string;
  avatar: string | null;
  isDeleted: boolean;
};

const DELETED_USER_FALLBACK = "Deleted User";

export function getUserDisplay(user: UserLike): UserDisplay {
  if (!user) {
    return {
      name: DELETED_USER_FALLBACK,
      email: "",
      avatar: null,
      isDeleted: true,
    };
  }
  return {
    name: user.name || user.email || DELETED_USER_FALLBACK,
    email: user.email || "",
    avatar: user.avatar || null,
    isDeleted: false,
  };
}
```

Note: This is a pure function that doesn't use `useTranslations()` directly (since it may be called server-side). Components that render the name can use the `isDeleted` flag to show the translated string instead:
```tsx

<span>{display.isDeleted ? t("common.deletedUser") : display.name}</span>
```
